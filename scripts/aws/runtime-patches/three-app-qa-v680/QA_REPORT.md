## 修正した問題

1. 画面の初期描画完了前に補助スクリプトがDOMを書き換え、Reactの再描画・ちらつきを誘発していた。プロフィール、スタイル、配信、登録メール再送、パスワード表示、発注画面などの起動順を修正。
2. サロンのサーバー側描画とブラウザ側描画で先頭要素が異なり、初期描画エラーになっていた。構成を一致させた。
3. 新規登録のログインID検証パターンが現行ブラウザで無効。不正入力や空パスワードがサーバー例外になる経路も修正。
4. マイページに残っていた旧「登録済みの店舗」を「サロンを探す」に統一。

## 残る確認範囲

- スマホは画面幅による検証。実機iPhone Safari・Android、カメラ、プッシュ通知、実回線の低速・切断は未検証。
- メール・SMSの画面遷移と内容はローカル捕捉で確認。実際の配送・受信や銀行連携は試していない。
- サロン・ディーラーは運営発行アカウントのため、顧客の自己退会とは別に運営からの利用停止を検証した。
- クーポン・ポイントの全条件、全メニュー・全権限の組合せ、全CSV入力、複数利用者の同時操作を網羅したものではない。
- 分納・返品・入金消込などのディーラーERPは既存のAPI統合回帰テストで確認。すべての例外経路をブラウザから操作したわけではない。
- サロン画面に旧カード課金状態APIへの410応答が残る。廃止済み機能への呼び出しで、今回の表示・操作を阻害しなかった。除去は別途整理対象。
- 管理者専用URLにスタッフが直接アクセスした際の403は正しく拒否するが、案内がJSON形式。専用エラー画面への改善余地がある。

詳細な自動実行結果はローカル `artifacts/three-app-qa-v680/audit.json` と `lifecycle.json`。個人情報や一時トークンを含み得るため、画面HTMLやメールログをリポジトリへ公開しない。
